# 역사 지명 지도 정확도 개선 설계

## 목표

본관과 거주지를 현대 지명 문자열로 추측해 표시하지 않고, 한국학중앙연구원 과거 합격자 데이터에 기록된 역사 지명을 식별 가능한 단위로 해석해 한반도 지도에 표시한다. 확인할 수 없는 지명은 임의 좌표에 배치하지 않으며 사용자에게 미확인 상태를 알린다.

## 현재 문제

- 지도 좌표표는 70개 지명만 포함한다.
- 본관 584개 중 63개, 거주지 428개 중 67개만 현재 매칭된다.
- `normalizePlace`가 괄호 안 한자를 제거하여 `영천(榮川)`과 `영천(永川)`을 같은 지명으로 만든다.
- 정확한 키가 없으면 앞 두 글자로 다시 검색하여 다른 지명에 잘못 연결할 수 있다.
- 좌표에 출처, 기준 시점, 정확도 정보가 없다.
- 본관 원자료는 한자를 보존하지 않아 지명만으로 동음이역을 구분할 수 없는 사례가 있다.

## 데이터 모델

역사 지명 자료를 애플리케이션 코드와 분리한 정적 TypeScript 데이터로 관리한다. 각 항목은 다음 필드를 갖는다.

```ts
interface HistoricalPlace {
  id: string;
  labels: string[];
  hanja?: string;
  modernArea: string;
  coordinate: readonly [latitude: number, longitude: number];
  precision: "settlement" | "county-center" | "regional-center";
  confidence: "verified" | "approximate";
  source: {
    title: string;
    url: string;
  };
}
```

- `id`는 한자까지 반영한 안정적인 내부 식별자다.
- `labels`에는 원자료 표기와 역사적 별칭을 넣는다.
- `precision`은 좌표가 읍치·군현 중심·광역 대표점 중 무엇인지 설명한다.
- `confidence`가 `approximate`인 항목은 지도와 상세 정보에서 근사 위치로 표시한다.
- 출처가 없거나 동음이역을 판별할 수 없는 항목은 등록하지 않는다.

## 지명 해석

지명 해석기는 부작용 없는 함수로 분리한다.

1. 거주지는 `한글(한자)` 전체 표기를 우선해 정확히 찾는다.
2. 이체자와 유니코드 호환 한자는 정규화된 별칭으로 명시한다. 한자를 제거해 자동 축약하지 않는다.
3. 본관은 `본관+성씨`별 예외 사전을 먼저 적용한다. 문헌상 동일 위치임이 확인된 경우에만 일반 본관명 항목으로 연결한다.
4. `미상`, `○○`, 빈 문자열, `기록 없음`은 미확인으로 처리한다.
5. 부분 문자열과 앞 두 글자 매칭은 사용하지 않는다.
6. 하나의 입력이 여러 장소 후보와 일치하면 미확인으로 반환한다.

반환값은 `resolved`, `ambiguous`, `unknown` 세 상태를 사용한다. UI는 `unknown`과 `ambiguous`를 지도에서 숨기되 개수와 이유를 표시한다.

## 좌표와 출처 기준

- 역사 지명의 현재 대응 지역은 한국민족문화대백과사전, 한국학중앙연구원 계열 자료, 국토지리정보원 지명 자료를 우선한다.
- 북한 지역은 신뢰 가능한 역사 지명 자료가 제시하는 현재 대응 지역을 사용한다.
- 정확한 옛 읍치 좌표를 확인할 수 있으면 `settlement`, 현대 시·군 중심만 확인되면 `county-center`, 도 단위처럼 넓은 값만 있으면 `regional-center`로 기록한다.
- OpenStreetMap 타일은 배경 지도일 뿐 역사 지명 검증 출처로 사용하지 않는다.
- 해외 본관이나 한반도 밖 지명은 한반도 지도 범위에서 제외하고 별도로 집계한다.

## 지도 표시

- 본관과 거주지는 해석 결과의 좌표만 사용한다.
- 동일 좌표의 거주지는 하나의 표식으로 묶고 상세 패널에 원래 지명별 건수를 표시한다.
- 근사 좌표는 확정 좌표와 다른 표식으로 구분하고 `근사 위치`라는 텍스트를 제공한다.
- 지도 하단에는 `표시 N곳 · 미확인 N곳`을 표시한다.
- 미확인 항목이 있으면 목록을 펼쳐 원자료 표기와 건수를 볼 수 있게 한다.
- 저작자 표시는 지도와 겹치지 않게 별도 하단 행에 유지한다.
- SSR과 클라이언트가 동일한 문자열 좌표와 크기를 사용하도록 모든 계산 결과를 고정 정밀도 문자열로 만든다.

## 파일 구성

- `src/lib/historical-places/types.ts`: 데이터와 해석 결과 타입
- `src/lib/historical-places/places.ts`: 출처가 포함된 역사 지명 데이터
- `src/lib/historical-places/resolve-place.ts`: 정확 매칭과 본관 예외 처리
- `src/components/KoreaMap.tsx`: 해석 결과 렌더링과 미확인 현황 표시
- `scripts/audit-map-coverage.mjs`: 전수 커버리지, 충돌, 출처 누락 검사
- 해석기 단위 검증 파일: 동음이역, 미상, 정확 매칭, 모호성, 좌표 범위를 검사

## 데이터 구축 범위

1차 완료 기준은 현재 `prisma/real-data.json`에 실제 등장하는 본관 및 거주지만 대상으로 한다.

- 거주지 428개 값을 모두 분류한다.
- 본관 584개 값을 모두 분류한다.
- `미상`, 공란, 판별 불가, 해외 지명도 분류 결과에 포함해 전체 합계가 원자료와 일치해야 한다.
- 문헌으로 확인 가능한 항목은 모두 좌표를 등록한다.
- 확인하지 못한 항목은 이유를 남기고 미확인으로 유지한다.

## 검증

테스트를 먼저 작성하고 실패를 확인한 후 구현한다.

- `영천(榮川)`과 `영천(永川)`이 서로 다른 좌표로 해석된다.
- `광주(廣州)`와 `광주(光州)`가 서로 다른 좌표로 해석된다.
- 본관 예외 사전이 성씨별 위치를 올바르게 선택한다.
- 앞 두 글자가 같은 미등록 지명은 다른 장소로 연결되지 않는다.
- 미상 계열 값은 `unknown`으로 반환된다.
- 모든 등록 좌표가 한반도 및 허용된 인접 범위 안에 있다.
- 모든 등록 항목에 출처 URL과 정확도 값이 있다.
- 전수 감사 결과에서 입력 개수는 `resolved + ambiguous + unknown`과 일치한다.
- `tsc --noEmit`, lint, production build를 통과한다.
- 실제 본관 상세 경로에서 남한·북한·동음이역 사례를 브라우저로 확인한다.

## 오류 처리와 공개 원칙

- 네트워크 지오코딩 API를 런타임에 호출하지 않는다. 결과 변동, 요청 제한, SSR 불일치를 피하기 위해 검증된 좌표를 저장소에 고정한다.
- 출처가 불충분한 좌표는 확정값으로 승격하지 않는다.
- 미확인 지명이 있어도 페이지 전체는 정상 렌더링한다.
- 지도는 원자료의 통계를 바꾸지 않으며, 위치 해석에만 관여한다.

## 완료 조건

- 기존의 추측 기반 `PLACE_COORDS`와 축약 매칭이 제거된다.
- 현재 데이터에 등장하는 모든 지명이 `resolved`, `ambiguous`, `unknown` 중 하나로 전수 분류된다.
- 확인 가능한 모든 남북한 역사 지명이 지도에 표시된다.
- 사용자가 확정 위치와 근사 위치, 미확인 항목을 구별할 수 있다.
- 자동 감사 결과와 주요 미확인 목록을 최종 보고한다.
